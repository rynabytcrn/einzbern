# Einzbern 4.4.0

Einzbern and Mana Orchestrate ship in lockstep at 4.4.0.

### Codex handoff and report delivery

- Install Codex PostToolUse and Stop hooks through the same setup, update and
  repair path as the existing engine hooks. Keep SubagentStop collectors retired.
- Use validated peer-batch receipts to stop a main conversation from repeatedly
  querying its coordinator after a successful handoff in the same turn. Explicit
  Owner input starts a new turn; unrelated targets and coordinator work remain available.
- Remind a coordinator to follow Mana Orchestrate when its recorded batch is
  terminal and ready to report but no delivery has been attempted. Repeated Stop
  and uncertain delivery outcomes end normally. A local final reply is not a
  cross-conversation send; retain the actual message receipt.
- Keep these guards conditional on existing batch evidence. They add no project
  fields, global polling quotas, automatic messages or model-stop guarantees.

### Recoverable storage and installation

- Check relocation destinations and writable boundaries before publishing new
  storage pointers. Retain recovery information when a later step fails, including
  failures after pointer publication, and expose the actual recovery state.
- Clarify device uninstall ownership and preserve shared libraries and unrelated
  host content. Keep installed paths relative to their declared runtime base.
- Ship the same generated guidance, hook registrations and diagnostics to fresh
  installations, updates, repairs and migrations without restoring old collectors.

### Shared coding guidance and agent context

- Publish the engine-owned coding guide through the existing Skill navigation
  and packaged references for supported hosts and models. Prefer readable control
  flow, explicit boundaries and changes justified by current behavior.
- Simplify configuration-backup and archive control flow while retaining their
  safety and recovery contracts. Keep generated helper files tied to their engine source.
- Bound agent-facing CLI context explicitly and retain a way to obtain complete
  evidence. A smaller response alone does not establish lower session cost.

### Release and verification correctness

- Preserve failed release subpackage enumeration as a failure instead of treating
  it as an empty successful result. Bind output sessions to the actual linked
  worktree while keeping release preparation on a physical Git checkout.
- Document behavior-based acceptance and reuse successful checks when their
  relevant inputs are unchanged. Keep the complete required release validation
  and actual publication evidence separate from local fixtures.
