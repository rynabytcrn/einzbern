Configuration contract
- The generated configuration-inventory.json contains 39 registered setting descriptors: 25 project, 4 library, 10 device. It also describes 14 independent configuration families. See specs/configuration-contract-v1.md for deterministic regeneration.
- Project/library events own portable declarations. Device files own host execution policies, device caps and absolute path bindings. The installed engine owns schemas and knowledge provenance policy. Generated AGENTS and handoff are consumers, not configuration authority.
- Historical model/quota declarations remain readable and explicitly labelled historical; new writes and removals refuse. Effective host policy is resolved separately, with revision/digest and an explicit host.
- New custom variables export nowhere unless explicitly selected for agents and/or handoff. Historical records without exports retain only the agents compatibility default. Both outputs withhold unsafe values and return value-free reasons.
- Shared path writes use relative locations or named binding references with safe child suffixes. Local bindings never enter shared event values. Historical absolute values retain their original meaning and require explicit migration before another device can use them reliably.
- Project output policy is shared. Generation=none stops future managed writes without deleting existing files. Device navigation selects local host integration, not shared document ownership.
