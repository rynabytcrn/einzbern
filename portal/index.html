Model categories
The parent table of the model tiers. The order column ranks the categories: the lower the order, the stronger the category, and escalation climbs toward the lower orders.
—

          

          
Project level: stored with this library and synced with it. A rule names a category and is given the category's tier with the largest order.

          

        

      

      

        

          

            
Model tiers
Every model a rule can be given, one record per row. The order column ranks all records together: the lower the order, the stronger the record. A category's tier with the largest order is the one a rule gets, and escalation moves to the next smaller order.
—

          

          
Project level: stored with this library and synced with it. Each tier is filed under a category from the model categories page.

          

        

      

      

        

          

            
Variables
Add, edit, rename and remove project variables. The order column sets the order AGENTS.md renders them in: variables with an order first, from the smallest, then the others by name.

          

          
Custom variables are stored with this library and rendered into AGENTS.md.

          

        

      

      

        

          

            
Gate configuration
Project gates are selected from changed paths and stored with this library. The order column sets the order gates are planned, run and listed in: gates with an order first, from the smallest, then the others by name.
—

          

          
Enabled gates run when their covered paths change. Required gates are checked before work is marked done.
