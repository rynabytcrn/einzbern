# 从 TCRN Workflow 迁移

迁移把旧版项目接入 Einzbern，并把旧记录导入新的 `.ether/` 库。它与恢复已有 Einzbern 库不同：恢复沿用现有 `.ether/`，迁移要先把旧工作区映射到新的项目和库。

## 迁移前准备

```text
einzbern setup --mode migrate --project <项目目录> --mapping <迁移映射 JSON> --at <UTC 时刻>
```

迁移映射说明旧项目、旧工作区与新库之间的对应关系。先不带 `--yes true` 生成 `SETUP_PLAN_READY`，核对逐库的事件头检查、目标位置、注册信息和将移动的文件；确认后再用 `--yes true` 执行。成功回执 `SETUP_APPLIED` 会列出写入、备份和自检结果。

## 迁移会保留什么

- 新记录写入独立的 `.ether/` 库，并登记到这台设备的 `registry.json`。
- 向导逐库对照迁移前后的事件头，帮助发现映射错误或不完整的导入。
- 旧版引擎和宿主配置先备份；需要移走的旧安装目录移入备份位置，不会删除其中的文件。
- 旧版工作区不会被新引擎原地重写。新引擎可以只读打开旧布局；尝试向旧布局写入会返回 `LEGACY_WORKSPACE_READ_ONLY`。需要在新库中继续追加记录时，必须先通过迁移导入。

旧设备目录、旧工作区和库目录用途不同。迁移计划会展示本次识别到的来源，不要只看名字相似就把它们互换。旧名与当前名的对应关系见[词汇表](Glossary.md)。

## 迁移完成后

确认项目在新设备注册表中指向预期的库，再用 `doctor --project <项目目录>` 检查引擎版本、技能副本、宿主钩子、注册信息、库格式与设备事件流。新库启用后，由新引擎写入新事件流；旧格式记录仍可只读查看，旧目录留作回退材料。

迁移支持随引擎版本逐步落地。如果当前版本返回 `SETUP_MIGRATE_PENDING`，不要重复尝试写入；当前版本尚未启用迁移执行，旧数据仍保留在原位置。
