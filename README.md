## 周三下午发生的事

周一，你在 Claude Code 里定了一件事：登录页的按钮改用设计系统的新组件，旧样式保留到 1.4。

周三，你在 Codex 里说「注册页也顺手改了」。它动手之前，上下文里已经有三行：周一那张 Story 和它的验收标准，那条「旧样式保留到 1.4」的决定，还有上周留下的一张卡片：这个组件在 Safari 下要补一个属性。

你没有粘贴任何东西，也没有提醒它去查。这就是 Einzbern 做的全部事情：记下来，在对的时候拿出来。

## 一台愿望机

圣杯是愿望机：许愿，得到结果。愿望机都有一个特点，愿望说得不具体，实现出来的很可能不是你要的。

Einzbern 照这个来。它只强制两件事：一张工单要写清目标，要写清怎样算完成。其余怎么写、怎么拆、怎么做，模型按自己的思路来，它不插手。

工单、知识、纪要、变量，是在这台机器里流转的魔力。它们被固定在项目目录下的 `.ether` 里。以太，魔力在现实中固定下来的介质。模型在每条 prompt 前从那里取，做完事往那里存。

## 它记什么

**愿：工单。** Initiative、Epic、Story、Subtask 四级。Story 是最小的完整意图，只索引它。工单之间的关系是字段：谁阻塞谁、谁实现谁、谁取代谁、由哪份纪要决定。不用另写一段话去解释。

> Story：登录页按钮改用 DS 组件。验收：默认、悬停、禁用三种状态与 Storybook 一致。

**决定：纪要。** 你的决定，和模型做的技术决定。每条决定有编号，工单与卡片用编号引用它。不要求模型开会讨论，只要求记下来。

> 纪要 D3：旧按钮样式保留到 1.4，1.5 移除。

**坑：知识。** 一张卡片记一条环境事实或教训，是没有任何工单或纪要以字段承载的那种东西。模型自己判断什么值得记，写入即可检索。旧卡只在被新卡冲突时退役。时间不是理由，容量也不是。

> 卡片：DS 按钮组件在 Safari 下要加 appearance: none，否则圆角丢失。

**变量。** 分宿主的模型档位表、项目的设计系统地址、你自己定义的键值。它们渲染进 AGENTS.md。你在 AGENTS.md 里写「实施用主力档」，Claude Code 与 Codex 各自换算成自己的模型。

## 它怎么出现在模型面前

每条 prompt 发出前，宿主把它交给引擎检索一次。有强相关的，就把标题送进上下文：

```
[Story 已完成] 登录页按钮改用 DS 组件 · 验收：三种状态与 Storybook 一致
[纪要 D3] 旧按钮样式保留到 1.4，1.5 移除
[卡片] DS 按钮在 Safari 需要 appearance: none
```

没有强相关的，就什么都不做。模型要正文时自己取。做完一件事，模型把结果记回工单，有决定记纪要，有教训写卡片。

## 什么时候你会想要它

- 任务跨了三天五个会话，第四天的模型还知道第一天定了什么。
- Claude Code 和 Codex 换着用，两边读同一份记忆。
- 夜里跑无人值守的批量实施，早上能追溯每一步做了什么、依据哪条决定。
- 桌面机在跑，你带着笔记本出门接着写。

目前面向单人多设备。多人共用一份记忆没有做。

## 为什么是它，而不是一个记忆插件

市面上的记忆方案大多是一个向量库或一叠笔记：把对话片段存起来，按相似度捞回来。它们记的是「说过什么」，Einzbern 记的是「决定了什么、要做什么、学到了什么」，三种记录各有结构，彼此用编号引用。

| 你需要的 | 记忆插件 | Einzbern |
|---|---|---|
| 一条决定和它的来龙去脉 | 一段相似的聊天记录 | 有编号的纪要，工单和卡片用编号指向它 |
| 一件事做到哪了 | 无 | 工单四级，关系是字段：谁阻塞谁、谁取代谁、由哪份纪要决定 |
| 换宿主 | 各记各的 | Claude Code 与 Codex 读同一个 .ether |
| 换设备 | 手动同步或不同步 | 放进云文件夹，每台设备一条流，同时写不冲突 |
| 想看、想改 | 翻文件 | Atelier：变量、规则、门配置、库状态一页管理，改了立刻渲染进 AGENTS.md |
| 模型的做事方式 | 插件不管 | 不管束；四条原则默认关闭，按项目自选 |
| 记录能不能被篡改 | 能 | 只追加的哈希链，改一条后面全对不上 |

变量是它区别于插件的另一半：分宿主的模型档位表、设计系统地址、你自己的键值，都在 Atelier 里改，渲染进 AGENTS.md，同一份规则文本在两个宿主上各自换算。

## 安装

Einzbern 由一个 skill 带进来：Mana Orchestrate。Mana 是流转的记忆，Orchestrate 是指挥它何时流向哪里。它教模型什么时候该调引擎的哪个功能，也带着安装向导。

用 skills 命令装：

```
npx skills add tpmoonchefryan/mana-orchestrate
```

或者对宿主说：找一个叫 Mana Orchestrate 的 skill，装上。

然后在项目目录里说：安装 Einzbern。向导问一屏问题：全新安装还是从已有的 `.ether` 恢复，生成物放哪，是否在云同步文件夹里，用什么语言，要不要在 AGENTS.md 写导航段。最后列出将写入的文件，你确认一次。更新、修复、从旧版迁移、卸载、体检，都是同一个向导的模式。

它不提交、不推送、不改你的 .gitignore、不删任何东西，除下载引擎外不联网。

## 日常怎么用

你正常工作，记忆自己出现。

想看或想改的时候，打开 Atelier。魔术师的工房，在这里是本机的一个网页：哪些原则启用了，变量是什么，门怎么配，记忆库现在什么状态。不常驻，用时打开。

AGENTS.md 是你的。Einzbern 只写带标记的段落：你启用的原则，和要渲染给模型的变量。段落被你改过，它就不再覆盖，怎么处理由你在 Atelier 里选。

内置原则一共四条，叫 Command Spell。令咒，对从者绝对有效的命令。它们不是强制的：默认全部关闭，你在 Atelier 里按项目自选启用，不启用也不影响记忆本身。

- 自主运行：不在任务中途问「要不要继续」，可逆的动作直接做，只有破坏性动作与范围变更才停。
- 批量处理：一次拆分产出的工单是一批，见红只记不修，批末一次处置，一批一次汇报。
- 无人值守指令：不用会弹确认框的写法，删除改为移动，命令里不 cd，只写工作目录。
- 静默汇报：工作进行期间不输出汇报，只在全部完成或全部阻塞时汇报。

## 多设备与云文件夹

`.ether` 可以放在 OneDrive、iCloud 这类同步文件夹里。每台设备只写自己的那条记录流，读取时合并全部流。两台设备可以同时写，没有锁，没有谁等谁。同一张工单被两边各改一次，后到的那次记为被拒，不丢，也不静默覆盖。索引与快照只在本机，云端只有记录本身。引擎不加密，云端账户的安全在你这边。

## 我们自己怎么用它

这是 Einzbern 自己的开发方式，也是我们建议的用法。你可以只用其中一层。

**两条对话。** 一条是设计对话，用旗舰档，和你讨论方向，把决定记成纪要，把要做的事拆成 Initiative、Epic、Story，写进 .ether。另一条是实施对话，用主力档，从 .ether 读 Story，不写代码，只派工、落链、跑门、汇报。

**一批做完。** 实施对话派一个经济档子代理把整个 Initiative 的 Story 一次拆成 Subtask，每张写明改动文件与依赖。然后按依赖与文件重叠分包：有关联的进同一包按序做，无关的各成一包。每包一个经济档子代理，在自己的 git worktree 上并行做，包完成即退役。全部完成后一个集成子代理按依赖合并，批末跑一次门、做一次验收，缺陷成批返工。

**四条原则都开着。** 自主运行：可逆动作直接做。批量处理：见红只记不修，批末一次处置。无人值守指令：不用会弹确认框的写法。静默汇报：只在全部完成或全部阻塞时汇报。

**你只在两个时刻出现。** 设计对话里做决定；实施对话收口时看一份汇报，里面待你决定的事项一次列全并附建议。

### 订阅与模型档位（截至 2026-09-26）

建议的订阅：Claude Max 5x 或 ChatGPT Pro 5x。并行子代理的上限按订阅定，超过建议值周限额掉得太快；上限在 Atelier 的 execution.maxConcurrentSubagents 里改。

| 订阅 | 并行子代理上限 |
|---|---|
| Claude Pro 或 ChatGPT Plus | 1 或 2 |
| Claude Max 5x 或 ChatGPT Pro 5x | 3 |
| 20x 档 | 8 或更高 |

并行也不是越多越好，额度快见底时要自动收缩。四个系统变量决定何时收缩，都在 Atelier 里改：

| 变量 | 默认 | 含义 |
|---|---|---|
| quota.fiveHourParallelOffPercent | 75 | 5 小时额度用到这个百分比，并行子代理上限降为 1 |
| quota.fiveHourWaitPercent | 90 | 5 小时额度用到这个百分比，不再派子代理，等窗口重置 |
| quota.weeklyParallelOffPercent | 95 | 周额度用到这个百分比，并行子代理上限降为 1 |
| quota.weeklyWaitPercent | 未设置 | 周额度不设等待阈值，设了才生效 |

下面是我们此刻的档位表，模型名会随厂商更新而过期，请以你在 Atelier 里维护的 models.tiers 为准。

| 宿主 | 旗舰档 | 主力档 | 经济档 |
|---|---|---|---|
| Claude Code | claude-fable-5-1，max，只用于设计对话，不派工 | claude-opus-5-5，max，子代理编排与验收 | claude-opus-5-5，low，拆分与分包实施 |
| Codex | gpt-6-astra，max | gpt-6-sol，max | gpt-6-luna，max |

## 预设规则怎么帮你把 token 花在刀刃上

四条原则不只是纪律，每一条都堵着一处实测过的浪费。数字来自 Einzbern 自己的开发记录，2026-09-26，同一批工作、同一模型。

| 浪费在哪 | 实测 | 哪条规则堵它 |
|---|---|---|
| 一个子代理连续跑，上下文越滚越大，每回合重读一遍 | 一个子代理做 30 张 Subtask：平均上下文 526k，3,740 回合，221M 加权 token，每张 7.4M | 批量处理：分包并行，每包一个新子代理，做完即退役。分包新子代理每张 2.9M，只有它的 39% |
| 中途见红就修，修完再红，门一遍遍重跑 | 前一版里 9 张缺陷单围着一条预算门转，同一个钩子缺陷分四次提交 | 批量处理：见红只记不修，批末一次处置，同一根因算一条 |
| 派一波正撞上额度窗口末尾，全部作废 | 8 个并行子代理在 12 分钟内打满 5 小时额度，零提交，约 15M 白花 | 额度门控：派前读额度，75% 降并行，90% 等重置 |
| 弹出确认框，会话无限等人 | 一次等了 2 小时 12 分 | 无人值守指令：不用会弹框的写法 |
| 主对话每派一次就写一段汇报 | 每段几千 token，都留在主对话上下文里，之后每回合重读 | 静默汇报：只在全部完成或全部阻塞时汇报 |
| 中途问「要不要继续」，等人回答 | 无人在场时一等就是整夜 | 自主运行：可逆动作直接做 |

成本的八九成是缓存读取，也就是每回合重读上下文。子代理启动时注入的系统提示与规则只有 52k，占单个子代理成本不到 1%。所以省 token 靠的不是少注入，是让每个子代理的上下文短、回合少：每包一份摘录文件而不是整份拆分文件，命令输出落盘只取尾部，大文件按段读，相邻命令合并。这些都写在批量处理原则和实施对话的启动文件里。

并行本身不省 token，它只改变花钱的速度；省 token 的是新上下文。所以并行上限按订阅定，额度门控在快见底时自动收缩。

## 为什么这样设计

**只提供记忆，不管束方法。** 前一版试过用门、证明和 Stop 钩子把模型框住，一百多个动词、十六道门。我们自己用了两个月：成本远高于收益，模型该忘的照样忘。这一版把它们去掉，留下记录与检索。

**钩子只有一条。** 模型不知道自己不知道什么，检索必须由宿主在每条 prompt 前触发，不能等模型想起来。但钩子里没有任何规则。取什么、给多少，引擎决定。

**AGENTS.md 是你的文件。** 规则要在两个宿主上同时生效，只能写在两个宿主都读的地方。所以 Einzbern 会写进去，但只写带标记的段，只写你启用的东西，改过就不碰。

**只索引 Story。** Initiative 与 Epic 太粗，Subtask 太碎。要知道的事，从 Story 就能知道。

**记录只追加。** 所有派生态都能从记录重建。索引可以只在本机、多台设备可以合并，都是因为这一条。

**配置分两层。** 项目级配置随记录同步，设备级配置留在本机。新装一台设备，重设的是设备，不是项目。
