# Antigravity host integration v1

This contract describes the candidate Google Antigravity (`agy` CLI, Antigravity IDE, and Antigravity 2.0 App) customization, Hook, native subagent, and headless CLI integration. It does not establish that an interactive surface fired a Hook in a particular session, or that a requested model, effort, or quota was actually selected by the provider.

## Separate surfaces and identity

`agy` CLI, Antigravity IDE, and Antigravity 2.0 App are independent surfaces sharing the Antigravity customization contract. `probeAntigravityHost` observes CLI availability with `agy --version` (falling back to `$HOME/.local/bin/agy` only when `PATH` is absent and no explicit executable override is supplied) and checks `.gemini/config`, `.gemini/antigravity-cli`, `.gemini/antigravity-ide`, and `.gemini/antigravity` independently. CLI availability does not prove IDE or App availability or selection. A version probe proves neither the surface used by a later session nor which model ran. Reported actual harness, selected surface, and subagent first-work signal remain `unknown` unless a per-session source proves them.

## Antigravity `hooks.json` contract

Antigravity reads user-scope Hooks from `${ANTIGRAVITY_CONFIG_DIR:-$HOME/.gemini/config}/hooks.json` and workspace-scope Hooks from `<project>/.agents/hooks.json`. Because Antigravity executes both user-scope and workspace-scope Hooks when both exist, Einzbern manages its owned `"einzbern"` hook group in the user-scope `${ANTIGRAVITY_CONFIG_DIR:-$HOME/.gemini/config}/hooks.json` so every project on the same home/device shares one active installation, and retires any redundant unedited `"einzbern"` group from `<project>/.agents/hooks.json` without creating new workspace `hooks.json` files or removing other projects' global dependency.

Einzbern manages only the top-level `"einzbern"` hook group inside `hooks.json`. All other top-level hook groups in both user and workspace files remain untouched. Managed entries are identified by exact structure and the complete canonical Einzbern Hook launcher command template (allowing only legitimate relative device-directory bindings). If an existing `"einzbern"` group or any of its `command` strings was modified outside Einzbern's expected shape, setup, update, repair, and uninstall refuse modification with `ANTIGRAVITY_HOOKS_OWNERSHIP_CONFLICT` and preserve the file for review. Backups are written before replacement and existing backups are never overwritten.

Every Antigravity Hook command that exits with status `0` must emit valid JSON on stdout; empty stdout on exit `0` is treated by Antigravity as a Hook parse error. Both the launcher shell wrapper and `einzbern-hook.mjs` emit `{}` (or `{"decision":"allow"}` for `PreToolUse`) whenever a project is unregistered, an invocation is skipped, recall yields no hits, or an internal non-blocking fallback occurs. Because Antigravity executes Hooks with the working directory set to the directory containing `hooks.json`, project resolution checks `payload.cwd` first and falls back to `payload.workspacePaths[0]`.

| Trigger | Behavior |
| --- | --- |
| `SessionStart` | Emits the navigation pointer via `injectSteps[].systemMessage.systemMessage` only when shared navigation in `AGENTS.md` was declined. |
| `PreInvocation` | Mapped internally to `UserPromptSubmit`. Runs recall on `lastUserInput` (or `prompt`) only when `invocationNum` is `0` (Antigravity's 0-indexed first model invocation) or omitted, covering both the first turn of a user prompt and the first turn of a spawned subagent conversation while skipping subsequent tool-loop invocations (`invocationNum !== 0` logs `HOOK_ANTIGRAVITY_INVOCATION_SKIPPED` and emits `{}`). Injects matching recall context via `injectSteps[].systemMessage.systemMessage`. |
| `PreToolUse` | Matcher `read_file\|view_file`. Inspects `toolCall.name` and `toolCall.args` (`Path`/`AbsolutePath`, 1-based inclusive `StartLine` and `EndLine`). For observed regular files strictly larger than 32 KiB (`32768` bytes), requires valid integer bounds `1 <= StartLine <= EndLine`, `EndLine - StartLine + 1 <= 200`, and window byte length `<= 32768`. Denials exit `0` with `{"decision":"deny","reason":"..."}`; allowed and unknown inputs exit `0` with `{"decision":"allow"}`. Shell commands are never parsed as file reads. |

## Hook and Skill locations

The global Skill copy is `${ANTIGRAVITY_CONFIG_DIR:-$HOME/.gemini/config}/skills/mana-orchestrate`. Selection detection checks `${ANTIGRAVITY_CONFIG_DIR}` when set, `.gemini/{config,antigravity-cli,antigravity-ide,antigravity}` under `$HOME`, and `<project>/.agents/hooks.json` (never bare `.agents`, which is shared with Codex Skill copies). The Skill-copy manifest (`skills.json` v2) records the Antigravity destination and digest. Updates preserve user-modified copies, and uninstall moves an Antigravity Skill copy only if its current bytes match the recorded ownership digest.

Doctor reports Antigravity CLI and surface observations alongside `selection` (`selected`, `not-selected`, or `unknown`) and `applicability` (`selected`, `not-selected`, or `selection-unknown`). When Antigravity is not selected, missing Antigravity Hooks or Skill copies do not fail traditional checks.

## Native subagent and headless CLI execution

Interactive Antigravity sessions delegate through Antigravity's native `invoke_subagent` tool under the general native execution protocol (`specs/host-fallback-v1.md`) using `hostKind: "antigravity"`, `invocationKind: "native-tool"`, `toolName: "invoke_subagent"`, and the device's `hosts.antigravity` model policy (`runner: "antigravity"`). Admission, recording, and read-only verification use `execution-host-prepare`, `execution-host-record`, and `execution-host-evidence`.

For headless CLI execution, `execution-antigravity-preflight` validates a saved `tcrn.host-native-preparation.v1` bound to `hostKind: "antigravity"` and `toolName: "agy"`. With `--reserve-output`, it reserves an empty private create-new artifact under the dispatch artifact guard and returns `{ destination, device, inode }`; without `--reserve-output`, preflight is read-only.

`skill/mana-orchestrate/scripts/agy-run.mjs` consumes a saved preparation and a create-new output path. After reserving and verifying the destination inode, it spawns `agy --input-format stream-json --output-format stream-json` with `shell: false`, sends a single-line NDJSON user message (`{"event":"user","message":{"content":prompt}}\n`) on stdin, passes `--model` for an explicit resolved selection, and passes `--effort` unless the explicit effort is `default`. It never passes `--dangerously-skip-permissions`. If final evidence persistence fails after saving the raw process return, the runner retains the private temporary `process-return.json` path so `execution-antigravity-record --binding <saved preparation> --result <process-return.json> --output <new private destination>` can recover the `tcrn.antigravity-process-evidence.v1` receipt, which `execution-antigravity-evidence` revalidates read-only. Process exit does not prove semantic task completion, and `actual.*` model/effort/usage fields remain `unknown` unless proven by documented host output.
